## 二、需求背景与现状盘点

### 2.1 业务背景

平台已具备登录认证能力（JWT + 验证码），但接口层面缺少授权控制：任何登录用户（甚至未登录请求）都能调用用户/角色/权限管理接口进行增删改查。随着 Agent、知识库、模型管理等业务模块逐步上线，权限失控将直接威胁数据安全（如任意用户可删除他人知识库、可给自己提权为超管）。

### 2.2 现状盘点（已实现，来自代码核查）

| 能力 | 状态 | 说明 |
|------|------|------|
| RBAC 数据模型 | ✅ | `users` / `roles` / `permissions` 三表 + `user_roles` / `role_permissions` 两张 M:N 关联表，`lazy="selectin"` 立即加载 |
| 认证（Authentication） | ✅ | JWT 登录（30 分钟有效期、HS256）、bcrypt 密码、图片验证码（fakeredis 存储） |
| 身份解析依赖 | ✅ | `get_current_user`：解析 JWT → 查询用户 → 校验 `is_active` |
| 超管标记 | ✅（字段存在） | `users.is_superuser` 字段存在，但**无任何消费方** |
| 用户/角色/权限管理页面 | ✅ | 前端 Users / Roles / Permissions 页面已对接真实后端 CRUD |
| **授权（Authorization）** | ❌ | **完全缺失**，详见差距分析 |

**接口规模现状**：`main.py` 已注册 11 个模块路由，合计约 75 条接口 —— auth 1 条、captcha 2 条（公开）；user 8 条、role 7 条、permission 6 条（系统管理，21 条）；knowledge 15 条、agent 10 条、prompt 8 条、tool 8 条、provider 6 条、model 5 条（业务模块，52 条）。

### 2.3 差距分析（Gap 清单）

| 编号 | 差距 | 影响 |
|------|------|------|
| **G1** | 鉴权覆盖缺失：约 75 条接口中仅 2 处使用 `get_current_user`（`GET /users/me`、knowledge 模块 1 处）；users/roles/permissions 全部 CRUD 接口**未登录即可调用** | 未认证即可增删改查用户/角色/权限，等同于后台裸奔 |
| **G2** | 无授权校验机制：不存在 `require_permission` / `check_permission` / `has_permission` 等权限校验依赖；`get_current_user` 只解决"是谁"，不解决"能做什么" | 登录即全权，RBAC 三表形同虚设 |
| **G3** | 权限模型扁平：`permissions` 表仅 `code/name/description`，无 `module` 分组字段（前端权限页已有"模块标签"概念，后端无对应字段）；无权限类型（menu/api/button）区分 | 权限码无组织，前端模块筛选无法落地，权限码增长后不可维护 |
| **G4** | 无权限缓存：每次鉴权需 user → roles → permissions 多表查询，且 `get_current_user` 每请求查库 | 高频接口性能劣化，NFR 无法达标 |
| **G5** | 前端无权限控制：侧边栏菜单固定显示、不按权限显隐；`AuthGuard` 仅校验登录态；无 403 页面与统一处理 | 无权限用户可见全部功能入口，体验混乱且诱导越权 |
| **G6** | 权限数据无初始化保障：`bootstrap_db.py` 灌入演示数据，但系统角色与权限码初始清单无定义；`is_superuser` 无消费方 | 全新环境无可用权限基线，超管直通语义未落地 |

## 三、头脑风暴记录（发散 → 收敛）

### 3.1 发散：候选方案清单

| 方案 | 思路 | 优点 | 缺点 | 结论 |
|------|------|------|------|------|
| **A. 接口级权限码校验依赖** | 新增 `require_permission(权限码)` FastAPI 依赖，逐接口显式声明 | 与现有依赖注入体系天然契合；显式声明、可读性强；粒度到接口；可组合 | 需逐接口挂接（约 75 条），有遗漏风险 → 用"鉴权矩阵 + 验收清单"兜底 | ✅ **选定（后端主方案）** |
| B. 中间件统一拦截 | 中间件按路径正则 → 权限码映射统一拦截 | 集中一处、接入成本低 | 映射关系隐式、路径与权限码难维护；特例（/me 等登录即可接口）多；与 FastAPI 依赖体系割裂 | ❌ 否决 |
| C. 引入 Casbin 等权限引擎 | 用成熟策略引擎管理授权 | 功能全面（RBAC/ABAC） | 与现有自研 RBAC 三表模型重复建设；引入新概念与依赖，学习维护成本高 | ❌ 否决 |
| D. 仅前端控制 | 菜单按权限显隐 + 路由守卫 | 实现简单、体验好 | 纯展示层，绕过前端即可越权，**不能作为安全边界** | ⭠ 作为 A 的**体验补充层**（不承担安全职责） |
| E. 启动时扫描路由自动注册权限 | 装饰器/扫描自动生成权限码与路由映射 | 自动化程度高 | 权限码语义依赖路由命名，初始权限清单不可控、难评审 | ❌ 本期否决（远期可选） |

**收敛结论**：主方案 = **A（后端接口级权限码校验）为主安全边界 + D（前端菜单/路由按权限过滤）为体验层**。B / C / E 否决理由存档备查。

### 3.2 权限模型演进决策

| 候选 | 思路 | 结论 |
|------|------|------|
| 模型1：扁平权限表 + `module` 分组字段 | 最小改动，与前端权限页"模块标签"对齐 | ✅ **选定** |
| 模型2：权限表增加 `type` 字段（menu/api/button 三类） | 语义更细，但当前菜单显隐与接口校验用权限码约定即可覆盖 | ❌ 本期不做，列入范围外 |
| 模型3：树形权限（父子继承） | 支持权限继承，复杂度显著上升 | ❌ 列入范围外 |

### 3.3 权限缓存策略决策

| 候选 | 思路 | 结论 |
|------|------|------|
| 缓存1：不缓存 | 每请求直查 user → roles → permissions | 实现最简，但每请求 2 次额外查询，NFR-1 有不达标风险 | 
| 缓存2：fakeredis 缓存 + 变更失效（TTL 30 分钟 + 写操作精确失效） | 命中时零查询；变更即时失效 | ✅ **选定** |
| 缓存3：JWT 携带权限快照 | 零查询 | 权限变更无法即时生效；token 膨胀；与"30 分钟有效期"叠加放大风险 | ❌ 否决 |

## 四、需求对齐记录

### 4.1 范围对齐（本期做 / 不做）

**本期做（In Scope）**：

1. 权限模型增强：`permissions` 表新增 `module` 分组字段
2. 全部已注册接口接入认证（未登录返回 401）
3. 权限校验依赖（`require_permission`）+ 系统管理模块（user/role/permission，21 条接口）鉴权矩阵落地
4. 业务模块（knowledge/agent/model/prompt/provider/tool，52 条接口）按同一规范预留权限码，鉴权矩阵在各自模块实现时逐条挂接
5. 权限解析服务 + fakeredis 缓存 + 变更失效
6. 前端：菜单按权限显隐、路由权限守卫、403 页面
7. `bootstrap_db.py` 系统角色与权限码初始化
8. 权限管理页面增强（模块分组筛选、按模块分组分配权限）

**本期不做（Out of Scope）**：详见第十节。

### 4.2 术语与约定对齐

| 术语/约定 | 对齐结论 |
|-----------|---------|
| 认证 vs 授权 | 认证（Authentication）= 确认"你是谁"（JWT，已实现）；授权（Authorization）= 确认"你能做什么"（本期实现） |
| 权限码规范 | 沿用前端既有约定 **`模块:操作`**（如 `user:list`、`role:assign_permissions`）；操作枚举对齐标准动作：`list / read / create / update / delete` + 业务动作（如 `assign_roles`、`assign_permissions`、`upload_document`） |
| 默认拒绝策略 | **已配置权限码的接口必须持有对应权限**；**未配置权限码的接口仅要求登录（认证）**——支持存量接口渐进加固，避免"一刀切全配"阻塞业务模块开发（对齐决策，见开放问题 Q3） |
| 超管语义 | `is_superuser=true` 直通全部接口，不依赖权限码配置；超管权限码清单仅作为页面展示参考 |
| 403 语义 | 对齐现有 `BizException` 约定：HTTP 200 + 业务码 `403`，`message="无权限执行此操作"`（开放问题 Q2 待最终确认） |
| 401 语义 | 维持现状：业务码 401，前端 `apiClient` 已实现 401 自动跳转登录 |

### 4.3 开放问题（待确认项）

| 编号 | 问题 | 倾向方案 | 状态 |
|------|------|---------|------|
| Q1 | 前端获取权限集合的接口形态：扩展现有 `GET /users/me` 返回 `roles + permissions`（推荐）vs 新增 `GET /auth/me/permissions` | 扩展现有接口，避免新增接口 | ⏳ 待确认 |
| Q2 | 403 的表达：业务码 403 + HTTP 200（对齐现有 BizException 约定）vs HTTP 403 状态码 | 对齐现有约定（HTTP 200 + code=403） | ⏳ 待确认 |
| Q3 | 未配置权限码的接口策略：仅要求登录（推荐）vs 全部显式配置权限码 | 仅要求登录，支持渐进加固 | ⏳ 待确认 |
| Q4 | 权限缓存 TTL：30 分钟（建议值）是否合适 | 30 分钟 | ⏳ 待确认 |
| Q5 | 危险操作（`role:assign_permissions`、`permission:delete`、`user:delete`）前端是否需要二次确认弹窗 | 需要（前端交互层增强） | ⏳ 待确认 |

> 开放问题不阻塞开发启动；确认后以变更记录形式回填本文档。

## 五、功能需求

### FR-1 权限模型增强（P0）

**描述**：`permissions` 表新增 `module` 字段（字符串，模块分组，如 `user` / `role` / `permission` / `knowledge`），与前端权限页"模块标签"对齐；存量权限数据按权限码首段回填 `module`。

**验收标准**：
- `permissions` 表含 `module` 字段，alembic 迁移可执行且可回滚
- 存量权限数据回填后无空值
- 权限码符合 `模块:操作` 规范（新增数据强制，存量数据逐步治理）

### FR-2 接口认证全覆盖（P0）

**描述**：全部已注册业务接口（约 75 条）必须经过 `get_current_user` 认证；未登录访问返回 401。auth（登录）、captcha（验证码）两个公开接口除外。

**验收标准**：
- 未携带 token 访问任意业务接口返回 401
- 系统管理 21 条接口 + 业务模块 52 条接口全部纳入认证覆盖清单
- 新增接口必须声明鉴权方式（写入开发规范，作为代码评审验收项）

### FR-3 权限校验依赖（P0）

**描述**：新增权限校验依赖（命名建议 `require_permission(权限码)`），语义链：认证 → 解析用户权限集合 → 校验权限码 → 不通过返回 403。支持一个接口声明多个权限码（默认 AND 语义）；`is_superuser=true` 直通。

**验收标准**：
- 无权限用户访问受限接口返回业务码 403
- 超管可访问全部接口（无需配置权限码）
- 多权限码接口：缺任一权限即 403

### FR-4 权限解析与缓存（P1）

**描述**：权限解析链 user → roles → permissions；请求内复用解析结果；跨请求使用 fakeredis 缓存用户权限集合（key 建议 `user_perms:{user_id}`，TTL 建议 30 分钟）。

**失效时机（精确失效）**：
- 用户角色变更（`PUT /users/{id}/roles`）→ 失效该用户缓存
- 角色权限变更（`PUT /roles/{id}/permissions`）→ 失效该角色全部用户的缓存
- 权限码更新/删除 → 失效引用该权限码的缓存

**降级**：缓存不可用时降级为直查数据库（fakeredis 为进程内存实现，故障概率低，但降级路径必须有）。

**验收标准**：权限变更后用户下一请求即生效；缓存命中时权限校验平均 RT 增量 < 10ms（见 NFR-1）。

### FR-5 未授权响应与前端权限控制（P0）

**描述**：
- 后端：无权限返回业务码 403（语义见 4.2）
- 前端：`apiClient` 识别 code=403 → 统一提示"无权限执行此操作"；新增 403 页面；路由守卫扩展为"登录 + 权限"双重校验，无权限页面跳转 403 页
- 侧边栏菜单按当前用户权限集合过滤显隐
- 权限集合获取方式按开放问题 Q1 的确认结论执行（倾向：扩展 `GET /users/me` 返回 `roles + permissions`）

**验收标准**：无权限用户看不到未授权菜单；直接输入 URL 访问无权限页面跳转 403 页；后端直连接口仍返回 403（前端控制不承担安全职责）。

### FR-6 权限数据初始化（P0）

**描述**：`bootstrap_db.py` 增加系统权限码初始清单（覆盖第八节鉴权矩阵全部权限码）与系统角色初始化：

| 角色 | 权限 |
|------|------|
| 超级管理员（`is_superuser=true`） | 直通全部接口，不依赖权限码配置 |
| 系统管理员角色 | user/role/permission 模块全部权限码 |
| 普通用户角色 | 各模块只读权限（`*:list`、`*:read`） |

系统内置角色标记不可删除（删除校验拒绝）。

**验收标准**：全新数据库 bootstrap 后，admin 可登录并访问全部接口；普通用户角色按矩阵权限访问，越权返回 403。

### FR-7 权限管理页面增强（P1）

**描述**：权限管理页列表支持按 `module` 分组筛选（模块下拉）；创建/编辑权限时可选择模块；角色分配权限弹窗按模块分组展示勾选。

**验收标准**：权限页可按模块筛选；角色分配权限弹窗按模块分组展示；现有权限页 CRUD 功能不回归。

### FR-8 拒绝访问审计日志（P2）

**描述**：403 拒绝访问记录结构化日志（loguru，含 user_id、所需权限码、请求路径、时间），供排查与后续审计模块使用。

**验收标准**：403 事件可从日志检索（按 user_id / 权限码过滤）。

## 六、非功能需求

| 编号 | 需求 | 指标 |
|------|------|------|
| NFR-1 性能 | 缓存命中时权限校验平均增量 RT | < 10ms；缓存未命中时单请求额外查询 ≤ 2 次 |
| NFR-2 安全 | 默认拒绝（deny-by-default） | 已配置权限码的接口必须持有对应权限；未配置权限码的接口仅要求登录（对齐 4.2 / Q3） |
| NFR-3 兼容性 | 不破坏现有前端对接 | `/users`、`/roles`、`/permissions` 已对接接口的响应结构不变；前端页面功能无回归 |
| NFR-4 可观测性 | 401 / 403 事件均有结构化日志 | 可按 user_id、路径、权限码检索 |
| NFR-5 可测试性 | 权限校验逻辑可单元测试 | 权限解析、缓存失效、超管直通、多权限码 AND 语义均可独立测试 |

## 七、数据模型变更说明（文字描述，不写代码）

1. `permissions` 表新增 `module` 字段（字符串，非空；存量数据按权限码首段回填）。
2. **不新增表**，不修改 `users` / `roles` / `user_roles` / `role_permissions` 结构 —— 现有 M:N 模型足以支撑本期授权能力。
3. alembic 迁移一个版本完成（含字段新增 + 存量回填）。
4. 权限码初始清单以第八节鉴权矩阵为准，随 `bootstrap_db.py` 灌入。

## 九、边界与异常场景

| 场景 | 预期行为 |
|------|---------|
| 未登录访问需登录接口 | 业务码 401，前端跳转登录页（现有逻辑） |
| 已登录但无权限 | 业务码 403，message="无权限执行此操作" |
| `is_superuser=true` | 直通全部接口，无需权限码配置 |
| token 有效期内权限被变更 | 缓存精确失效后，用户下一请求即按新权限执行 |
| 用户角色被变更 | 失效该用户权限缓存，下一请求生效 |
| 角色被删除 | 失效持有该角色用户的权限缓存 |
| 权限码被删除但接口仍引用 | 校验失败按 403 处理（默认拒绝）；开发规范要求删除权限码前同步清理接口引用 |
| 账号被禁用 | 401（现有 `get_current_user` 逻辑） |
| 缓存服务不可用 | 降级直查数据库，功能不中断 |
| 前端直接输入无权限页面 URL | 路由守卫拦截 → 403 页 |

## 十一、验收标准（汇总）

| 编号 | 验收项 |
|------|--------|
| AC-1 | 未登录访问任意业务接口 → 401 |
| AC-2 | 无权限用户访问受限接口 → 403 |
| AC-3 | 超管访问全部接口 → 200 |
| AC-4 | 权限变更后用户下一请求生效（缓存失效验证） |
| AC-5 | 全新库 bootstrap 后：admin 可登录并访问全部接口；普通角色按矩阵访问，越权 403 |
| AC-6 | 前端：无权限菜单不显示；直接输入 URL → 403 页 |
| AC-7 | 现有前端页面（用户/角色/权限管理）功能无回归 |
| AC-8 | 缓存命中时权限校验平均增量 RT < 10ms |
