# 项目启动注意事项说明书

> 适用环境：Windows（本项目当前在一台 Windows 11 + Python 3.14.8 + Node 22 的机器上完成启动验证）。
> 更新日期：2026-11-07

## 1. 项目概览

| 项 | 说明 |
|----|------|
| 后端 | FastAPI + SQLAlchemy(async) + SQLite，默认监听 `127.0.0.1:8080` |
| 前端 | React 19 + TypeScript + Vite，默认监听 `localhost:5173` |
| 数据库 | SQLite 文件库 `chenguang.db`（**免 Docker**，无需 MySQL） |
| 缓存 | fakeredis 内存实现（**免 Docker**，无需 Redis） |
| 对象存储 | 真实 MinIO 客户端（默认 `127.0.0.1:9000`，**未启动时文件上传不可用**） |

## 2. 前置环境要求

| 依赖 | 最低版本 | 本机验证版本 |
|------|----------|--------------|
| Python | 3.10+ | 3.14.8 |
| Node.js | 18+ | 22.22.2 |
| npm | 随 Node 附带 | 10.9.7 |
| Git | 任意 | 2.55.0.windows.3 |

> 说明：`AGENTS.md` 中标注目标 Python 为 3.13，但项目在 3.14 下亦可运行（见第 6 节“已知问题与排错”）。

## 3. 一键启动（推荐）

双击项目根目录的 `start.bat`，脚本会依次完成：

1. **检查 Python**：未安装则提示安装并勾选 “Add Python to PATH”。
2. **创建虚拟环境** `.venv`（首次）。
3. **安装后端依赖**：`pip install -r requirements.txt`（默认走清华镜像源）。
4. **初始化数据库**：`bootstrap_db.py`（建表 + 灌入演示数据 + 标记迁移版本）。
5. **安装前端依赖**：`npm install`（首次，位于 `app/`）。
6. **启动后端与前端**：分别监听 8080 / 5173，并用 `wait_ready.py` 轮询就绪。
7. **打开浏览器**：自动跳转 `http://localhost:5173`。

脚本会检测端口占用，端口已被占用时跳过对应服务、不重复启动，因此**重复执行是安全的**。

## 4. 访问地址与默认账号

| 地址 | 说明 |
|------|------|
| http://localhost:5173 | 前端界面 |
| http://localhost:8080/health | 后端健康检查（返回 `{"status":"ok"}`） |
| http://localhost:8080/docs | 后端 API 文档（Swagger） |

默认账号：`admin` / `123456`

## 5. 手动启动

后端（在项目根目录）：

```
.venv\Scripts\python.exe -m uvicorn src.main:app --host 127.0.0.1 --port 8080
```

前端（在 `app` 目录；本机 PowerShell 执行策略禁用了 `npm.ps1`，**必须用 `npm.cmd`**）：

```
npm.cmd run dev
```

## 6. 已知问题与排错

### 6.1 虚拟环境 ABI 不匹配（`_cffi_backend` / `_greenlet` / `_imaging` 等模块缺失）

**现象**：启动后端时报 `ModuleNotFoundError: No module named '_cffi_backend'`（或 `_greenlet`、`_imaging`、`_argon2_cffi_bindings` 等）。

**原因**：`.venv` 是在旧版 Python（如 3.13）下安装的，编译型扩展（`.pyd`）带 `cp313` 标签；换到 Python 3.14 后 ABI 不兼容，无法加载。

**解决**：删除 `.venv` 后重新运行 `start.bat`，或手动强制重装这几类易碎包：

```
.venv\Scripts\python.exe -m pip install --force-reinstall --no-deps cffi greenlet argon2-cffi-bindings pillow PyYAML -i https://pypi.tuna.tsinghua.edu.cn/simple
```

> `start.bat` 已在依赖检查失败时自动执行上述强制重装，以修复“已安装但 ABI 损坏”的包。

### 6.2 依赖安装缓慢 / 超时

国内网络访问 PyPI 默认源较慢。`start.bat` 已默认使用清华镜像源。也可全局配置：

```
pip config set global.index-url https://pypi.tuna.tsinghua.edu.cn/simple
```

### 6.3 MinIO 未启动，文件上传功能不可用

后端启动日志若出现 `minio 桶创建失败，文件上传功能将无法使用`，属**预期行为**——本地免 Docker 模式下没有运行 MinIO 服务。影响范围：知识库文档的上传/下载等对象存储功能。

如需启用文件上传，二选一：
- 启动 MinIO：`docker compose -f docker/docker-compose.yaml up -d`（需 Docker）；
- 或将 `src/infra/minio_client.py` 改为使用仓库中已存在的 `src/infra/mock_minio.py`（进程内存实现，重启即失效）。

### 6.4 端口被占用

`start.bat` 会自动跳过已占用的端口。如需手动释放，例如释放 8080：

```
netstat -ano | findstr :8080
taskkill /PID <PID> /F
```

### 6.5 数据库损坏 / 迁移失败

`bootstrap_db.py` 会自动把旧库备份为 `chenguang.db.bak_<时间戳>` 后重建，不会直接丢数据。备份文件可按需删除。

## 7. 关键脚本说明

| 文件 | 作用 |
|------|------|
| `start.bat` | 一键启动入口（**必须保存为 GBK 编码 + CRLF 换行**） |
| `bootstrap_db.py` | 数据库引导：首次建库灌演示数据、迁移升级、异常时备份重建 |
| `init_data.py` | 建表并写入演示数据（幂等，可重复执行） |
| `wait_ready.py` | 轮询等待前后端就绪，供 `start.bat` 调用 |
| `requirements.txt` | 后端依赖清单（含 `minio` 及其传递依赖 `argon2-cffi`） |

数据库迁移仍使用 alembic：`python -m alembic upgrade head`。

## 8. 编码约定（重要）

- `start.bat` 必须保持 **GBK 编码 + CRLF 换行**。CMD 在 `chcp 65001` 下读取 UTF-8 批处理会出现文件指针错乱；纯 LF 换行会拆断 `if`/`for` 等复合语句。修改该文件请使用支持 GBK 的编辑器，或通过脚本保留原编码。
- 其余代码文件（`.py`、`.ts`、`.md`、`.json` 等）均为 UTF-8。
